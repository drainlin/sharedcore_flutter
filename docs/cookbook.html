Overview

插件边界

Flutter App 只通过稳定的 Dart 接口使用插件；网络、签名和 Session 刷新由插件内部完成。

Flutter App页面、状态管理、Session 持久化、商店 SDK
↓
sharedcore_flutter全局单例、设备信息自动采集、网络请求、签名、Session 刷新、模型转换与稳定异常类型

直接作为 Flutter 插件使用

添加依赖后通过公开 Dart API 调用，不需要配置额外的开发环境。

网络由插件管理

插件负责请求、证书校验、签名和错误转换，不需要 App 注入 HTTP 客户端。

宿主仍有职责

商店购买和文件选择仍由 Flutter App 完成；插件自动读取设备元数据并安全维护 Session 凭据。

只导入公开入口：package:sharedcore_flutter/sharedcore_flutter.dart。不要导入 src/ 下的文件。

Installation

添加插件

当前插件适合通过私有仓库或本地路径接入；发布方式确定后只需替换 dependency 来源。

最低版本：Flutter 3.38.0，Dart 3.10.0。
pubspec.yaml · 本地开发
dependencies:
  flutter:
    sdk: flutter
  sharedcore_flutter:
    path: ../sharedcore_flutter
Dart · 唯一推荐导入
import 'package:sharedcore_flutter/sharedcore_flutter.dart';
请整体升级插件包。不要从不同版本中单独复制文件；升级依赖后应重新执行 Android/iOS 构建。

Upgrade

从 0.2.1 升级到 0.3.0

0.3.0 整体替换了底层实现，并且不提供旧 API 兼容层。推荐先替换插件并修复编译错误，再处理 Session 与平台配置，最后重新构建原生产物。

设备信息自动采集

删除必填的 SharedCoreDeviceConfiguration；多数 App 不再传设备信息。

Session 自动持久化

Android 和 iOS 都会自动恢复、保存和清理完整 Session。

购买验证统一

四个平台/类型方法合并为 verifyPurchase，平台和商品类型自动判断。

异常来源二选一

后端错误读取 backendCode，本机错误读取 localError。

推荐升级顺序

  1. 整体替换 0.3.0 插件包，执行依赖更新并修复 Dart 编译错误。
  2. 删除旧的设备配置，确认签名密钥和 Endpoint 路径模式。
  3. 修改 Session 恢复、图生图、购买验证、兑换码和异常处理代码。
  4. 补充所需平台配置，清理旧构建缓存并重新构建 Android/iOS。

Session 迁移

SharedCore.configure 会自动恢复、验证或创建 Session。应用不再读取、保存或注入凭据。iOS 自动把旧 UserDefaults 凭据迁移到 Keychain；Android 自动把插件旧有的明文 SharedPreferences 凭据迁移为 Android Keystore 加密密文。

App 自选存储无法自动发现。0.2.1 Android 如果把凭据放在宿主任意位置，升级后会建立新 Session；当前版本不再提供公开导入入口。

路径与测试服

bundleDerived（默认）

根据运行时 Bundle ID/包名派生路径，同时派生 JSON noise 前缀并固定为 20 项。

builtIn

使用插件保护的内置路径，需要时显式指定。

0.2.1 如果只覆盖了少量 Endpoint，不能把原映射直接用于 custom；当前默认使用 bundleDerived，后端仍使用内置路径时需显式选择 builtIn。testServerMode: true 优先级最高，会强制使用内置测试服地址和未混淆真实路径。

购买验证迁移

Dart · 统一购买验证
final result = await client.verifyPurchase(
  productId: purchase.productID,
  purchaseData: platformPurchaseData,
);

iOS 的 purchaseData 是 Apple receipt data，Android 是 Google Play purchase token。只有 v2 商品目录 creditPage.purchaseList 中的商品按一次性内购验证，其他已知商品全部按订阅验证。插件会按需加载并缓存商品目录；找不到商品时抛出 SharedCoreLocalError.purchaseProductNotFound。

异常迁移

Dart · 0.3.0 错误分流
try {
  await client.loadHomeContent();
} on SharedCoreException catch (error) {
  if (error.isBackendError) {
    handleBackendError(error.backendCode!, error.message);
  } else {
    handleLocalError(error.localError!, error.message);
  }
}

后端错误只有 backendCode，本机错误只有 localError；二者不会同时存在。message 分别承载后端返回消息或本机诊断信息，httpStatus 只有在能够取得状态码时才非空；调用者还可以通过 isRetryable 和 isAuthenticationError 决定重试或展示登录提示。

Endpoint 配置删除

SharedCoreEndpoint、endpointPaths 和 SharedCoreApiPathMode.custom 均已删除。业务调用方法不变，调用方只需删除旧路径配置。

模型与平台变化

  • SharedCoreReplacementApp.schema 和 hasTarget 已删除；isEnabled 只读取后端 enabled/newAppEnabled。
  • SharedCorePurchaseVerificationResult.shouldDiscardReceipt 已删除。
  • SharedCoreSession 已删除，凭据不会进入公开模型。
  • 0.3.0 只支持 Android ARM64、iOS ARM64 真机和 Apple Silicon 模拟器，不支持 x86、x86_64 或 32 位 ARM。
  • iOS 检测微信/QQ 需要宿主配置 LSApplicationQueriesSchemes；Android package visibility 已由插件声明。
升级后必须重新构建。不要混用 0.2.1 与 0.3.0 的 Dart 文件、生成代码或原生二进制，也不要沿用旧插件的构建缓存。

需要逐项核对时，请查看项目根目录的 完整 0.3.0 迁移指南。

Quick Start

配置全局客户端

SharedCore.configure 会自动完成插件初始化并采集 Android/iOS 设备信息，调用方不需要单独执行初始化方法。

Dart · 完整的最小配置
import 'package:sharedcore_flutter/sharedcore_flutter.dart';

Future<SharedCoreClient> createSharedCoreClient() async {
  final client = await SharedCore.configure(
    const SharedCoreConfiguration(
      baseUrl: 'https://api.example.com',
      appId: 'your-app-id',
      signSecret: null, // 使用插件内置的默认签名密钥
    ),
  );

  return client;
}
生命周期是进程级单例。后续通过 SharedCore.instance 使用；相同配置重复调用会返回同一个实例，不同配置会抛出 SharedCoreLocalError.alreadyConfigured。
通常不需要传 deviceOverrides。设备标识、App 版本、系统信息、语言、时区、输入语言、VPN、微信/QQ 和运营商信息会在配置时自动采集。
iOS 应用检测：如果需要自动判断微信或 QQ，请在宿主 Info.plist 的 LSApplicationQueriesSchemes 中保留 weixin 和 mqq。Android 所需的包可见性查询已由插件声明。
XML · iOS Runner/Info.plist
<key>LSApplicationQueriesSchemes</key>
<array>
  <string>weixin</string>
  <string>mqq</string>
</array>

覆盖或补充设备信息

只有业务侧掌握的值才需要传入。字段非 null 时覆盖自动采集结果，因此布尔值可以明确覆盖为 true 或 false。

Dart · 仅填写业务侧掌握的值
const configuration = SharedCoreConfiguration(
  baseUrl: 'https://api.example.com',
  appId: 'your-app-id',
  deviceOverrides: SharedCoreDeviceOverrides(
    templateLanguage: 'zh-CN',
    installReferrer: 'campaign', // 平台无法自动获得时由业务补充
  ),
);

自定义网络参数

Dart · 网络配置
const http = SharedCoreHttpConfiguration(
  connectTimeout: Duration(seconds: 60),
  readTimeout: Duration(seconds: 60),
  proxyUrl: null,
  userAgent: 'my-product/1.0.0',
  maxResponseBodyBytes: 16 * 1024 * 1024,
);

final configuration = SharedCoreConfiguration(
  baseUrl: 'https://api.example.com',
  appId: 'your-app-id',
  requestTimeout: const Duration(seconds: 60),
  http: http,
);

选择 API 路径模式

apiPathMode行为
SharedCoreApiPathMode.bundleDerived（默认）使用 Android 包名或 iOS Bundle ID，为每个 Endpoint 自动生成确定性的混淆路径；JSON noise 前缀也自动生成，字段数固定为 20。
SharedCoreApiPathMode.builtIn使用插件保护的内置 API 路径；JSON noise 使用调用者配置。
Dart · 使用 Bundle ID 混淆路径
final configuration = SharedCoreConfiguration(
  baseUrl: 'https://api.example.com',
  appId: 'your-app-id',
  apiPathMode: SharedCoreApiPathMode.bundleDerived,
);
混淆模式需要服务端支持。应用侧无需生成路径、JSON noise 前缀或传入 Bundle ID；插件会自动读取当前 Android 包名或 iOS Bundle ID 并完成处理。在该模式下，调用者传入的 jsonNoisePrefix 和 jsonNoiseFieldCount 会被忽略。该模式不替代登录鉴权或请求签名。
测试服模式优先级最高。testServerMode: true 会忽略 apiPathMode，使用受保护的内置测试服地址与内置路径，也不要求 Bundle ID 派生条件。

Session

恢复、刷新与退出

Android 和 iOS 都会在配置客户端时自动恢复、验证或创建 Session，并在凭据变化后自动安全保存。应用无法读取或注入凭据。iOS 使用 Keychain；Android 使用 Keystore 密钥加密后的插件私有存储。

Dart · 启动流程
final client = await SharedCore.configure(configuration);

// configure 已自动恢复并验证凭据，或创建匿名 Session。
final account = await client.refreshAccount();
Dart · 登录与退出
final account = await client.login(
  email: email,
  password: password,
);

// 登录成功后自动安全持久化；退出后自动切换到匿名 Session。
await client.logout();

首次安装

configure() 自动创建匿名 Session，无需额外启动调用。

恢复登录

configure() 自动恢复 Session；检测到已有安全凭据后直接刷新账号。

并发过期

授权请求遇到 Session 失效时，插件会合并并发刷新；刷新凭据仍被拒绝时清除旧凭据、匿名恢复并只重试一次。

离线恢复：网络或服务暂时不可用时保留可能仍有效的凭据；若旧凭据已确认失效，即使匿名创建随后失败也会先从安全存储删除旧值。后续业务请求会自动补建匿名 Session。
删除 App 后不会恢复旧账号凭据。Android 沙箱和 Keystore 会随卸载清理；iOS 重装首次启动会通过新的安装标记删除仍留在 Keychain 的旧凭据。

Purchases

商店购买与服务端验证

插件会根据当前运行平台自动选择 Apple 或 Google 验证接口，并根据 v2 商品目录自动判断一次性购买或订阅。发起购买、恢复购买和监听交易仍由 StoreKit/Google Play 对应的 Flutter 插件完成。

Dart · 通用验证入口
final result = await client.verifyPurchase(
  productId: purchase.productID,
  purchaseData: purchaseData,
);

if (result.isSuccess) {
  await client.refreshAccount();
}

一次性购买

只有 v2 creditPage.purchaseList 中的商品会走一次性内购验证。

订阅

v2 商品目录中的其他商品全部走订阅验证。

iOS purchaseData

传入 Apple receipt data。

Android purchaseData

传入 Google Play purchase token。

无需提前加载目录。如果 App 尚未调用 loadPurchaseCatalog()，首次验证时插件会自动加载并缓存 v2 商品目录。找不到 productId 时会抛出 purchase_product_not_found，不会猜测购买类型。

Errors

统一捕获 SharedCoreException

插件内部的网络、后端业务和本机错误都会转换为稳定的 SharedCoreException。一个异常只会属于后端错误或本地错误，不需要同时判断多套错误字段。

Dart · 错误分流
try {
  final home = await client.loadHomeContent();
  emit(HomeReady(home));
} on SharedCoreException catch (error) {
  if (error.isRetryable) {
    scheduleRetry();
  } else if (error.isAuthenticationError) {
    emit(LoginGuidanceRequired(error.message));
  } else if (error.isBackendError) {
    // backendCode 和 message 均来自后端响应。
    emit(HomeBackendFailure(
      code: error.backendCode!,
      message: error.message,
    ));
  } else {
    switch (error.localError!) {
      case SharedCoreLocalError.network:
      case SharedCoreLocalError.timeout:
        emit(HomeNetworkFailure(error.message));
      default:
        emit(HomeLocalFailure(error.message));
    }
  }
}
backendCode
后端响应中的业务码。本地错误时为 null。
localError
本地错误枚举。后端业务错误时为 null。
message
后端错误时是后端返回的 msg/message（缺失时使用插件提供的说明）；本地错误时是本机诊断信息。
httpStatus
可以取得 HTTP 状态码时返回；否则为 null。
isBackendError
backendCode != null 的便捷判断。
isLocalError
localError != null 的便捷判断。
isRetryable
网络、超时、408、425、429 和 5xx 等瞬时失败为 true。
isAuthenticationError
SDK 已尝试内部 Session 恢复，但操作仍存在凭据拒绝时为 true。
不会同时出现两种来源。后端返回业务失败时只设置 backendCode；网络中断、超时、参数校验、解析失败、平台能力等问题只设置 localError。没有业务 envelope 的 401/403/404/5xx 分别归类为 unauthorized、forbidden、notFound、server，并携带可取得的 httpStatus。
安全存储错误不会被隐藏。如果一次业务失败同时触发 Session 写入或删除，而 Keychain/Keystore 操作失败，调用者会收到 sessionStorageUnavailable，因为此时凭据状态不能被认为已可靠保存。
